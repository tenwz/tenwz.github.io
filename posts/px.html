px: 让任何运行 Pi 的机器成为 Agent 服务

2026-09-13

1. 概述

PX 为 Pi 提供与 OpenAI Agents API 一致的接口，使应用、服务和其他 Agent 能够以标准方式调用运行在本机上的 Pi。

PX 不引入新的 Agent Runtime，也不创建新的运行环境：

  • Agent 逻辑仍由 Pi 负责
  • 代码、工具、凭证、环境仍留在本机
  • Session 状态由 PX 持久化，Agent 进程无需常驻
应用
  ↓
Agents API
  ↓
PX
  ↓
Pi
  ↓
本机环境

2. 快速开始

# 启动服务
px serve

# 连接外部服务
px connect github
px connect gmail
px connect slack

启动后，本机 Pi 即可通过 Agents API 兼容接口被外部应用访问。

3. 核心概念

3.1 Serve：让应用找到 Pi

PX 将本机 Pi 暴露为符合 OpenAI Agents API 规范的服务端点。应用可以：

  • 发起新任务（创建 Session）
  • 继续已有 Session
  • 接收执行过程与结果
  • 断开连接后随时回来（Session 不随连接消失）

3.2 Connect：让 Pi 访问外部世界

通过 px connect <service> 将外部服务注册为 Pi 的可用能力。连接后 Pi 可以：

  • 读取 GitHub Issue
  • 搜索、读取 Gmail 邮件
  • 发送 Slack 消息
  • 检查部署状态

凭证在连接时完成授权，不进入对话上下文。Pi 只感知到“这些操作现在可以执行”。

3.3 Session：工作的基本单位

Agent 的工作很少在一次请求内结束。一次 Bug 调查可能演变为修改，修改进入 Review，Review 又引出新的问题。因此 PX 以 Session 而非 Request 为持续工作的基本单位：

请求 → Session → 工作 → 停止
                       （任意时间间隔）
请求 → 同一个 Session → 继续工作
  • Session 的上下文被持久化
  • Agent 进程停止后 Session 仍然存在
  • 下一次请求通过 Session ID 恢复到同一上下文

3.4 Watch：让 Session 在未来醒来

PX 允许一个 Session 在停止前留下 Watch，声明“什么条件值得让我恢复”。条件命中时，PX 恢复该 Session，原有上下文完整保留。

Session
   ↓ 留下
 Watch
   ↓ 等待
条件命中
   ↓
恢复同一个 Session

一个 Session 可以同时持有多个 Watch：

Session
  ├── Watch: Gmail
  ├── Watch: GitHub
  ├── Watch: 新用户注册
  ├── Watch: 市场行情
  └── Watch: 时间

4. Watch 详解

4.1 声明方式：由 Agent 创建，而非人工配置

Watch 不需要用户编写规则语言（如 ON event WHERE ... THEN ...）。用户只需用自然语言表达意图：

“如果老板给我发邮件，告诉我。”

后续工作由 Agent 自行决定：

  • 观察什么数据源
  • 检查频率
  • 什么算“老板的邮件”
  • 判断是否需要模型参与
  • 何时停止观察

4.2 条件判断的两级模型

代码级判断——条件可确定化为布尔逻辑时，不唤醒 Agent，也不调用模型：

事件 → 代码判断 → true → 恢复 Session

适用场景：

  • 收到来自特定邮箱的邮件
  • CI 构建失败
  • 股价上涨超过 5%
  • 第 100 个新用户注册

AI 级判断——条件需要语义理解时，由一个小型判断 Agent 评估：

事件 → AI 判断 → true → 恢复 Session
              ↘ false → 不动作

判断 Agent 只需回答一个问题：“现在值得叫醒它吗？”

适用场景：

  • 有“重要”邮件时通知我
  • 出现异常用户行为时提醒我
  • 客户明显不满意时介入
  • 等到“这件事值得继续处理”时再回来

4.3 时间是一种特殊事件

定时触发不调度整个 Agent，而是调度一次“注意力检查”：

时间到 → 检查 → 有值得处理的变化？→ 否：什么都不发生
                                   → 是：恢复 Session

因此：

  • “明天再看” = 明天做一次检查
  • “每天早上检查一次” = 每天一次注意力检查，而非每天运行完整 Agent
  • “一直检查直到 Release 发布” = 重复检查，命中即停

4.4 动态规划：下一步在下一步决定

Watch 可以链式产生。Session 因某事件醒来后，处理完当前工作可以再留下新的 Watch：

Session → Watch A → 事件 A → Session → Watch B → 事件 B → ...

无需预先定义完整 Workflow。示例：邮件中提到“API 下周发布”→ 处理邮件 → 留下 Watch“发布后再检查一次”→ 停止。

4.5 资源模型：Agent 无需常驻

工作（分钟级） → 停止（天级） → 事件命中 → 恢复

长期运行的不是进程，而是 Session + Watch 的组合。

职责划分：

组件 职责
Pi Agent 推理与执行
本机 环境：代码、工具、凭证
外部服务 各自的数据与事件
PX 连接以上三者：Serve（暴露）、Connect（接入）、Watch（唤醒）

一句话描述 PX

PX 为运行在本机的 Pi 提供与 OpenAI Agents API 一致的接口，并通过 Connect 接入外部服务、Watch 让已停止的 Session 在条件命中时自动恢复，使任何一台机器都能成为可持久工作的 Agent 服务。
